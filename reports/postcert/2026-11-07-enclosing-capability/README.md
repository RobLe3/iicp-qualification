## Scenario labels are not complete contracts

The three SDK cross-flavor cases each select four routing-policy refusal vectors: missing encryption key, disallowed region, insufficient manifest identity and incompatible payload-retention policy. Those negative vectors do not demonstrate a positive authorized-provider path, a local ranker invocation or the full general capability Profile. The static submit code filters routing-policy eligibility before candidate selection and an optional local ranker; that is not the same as proving all general capability matching or provider authorization.

PHP selects a registration recovery/operator rollback test, followed by installed TCP/kernel comparison and discovery/endpoint observers. Rust's declared pure behavior-fixture test is not the literal installed path: its accepted adapter instead selects explicit installed-binary registration, discovery and endpoint postconditions. Product and accepted-harness revisions are pinned separately. These are source/dispatch interpretations of existing accepted records, not fresh runtime observations or independent reproduction.

## Measured extension-name difference

Separate ordinary source-fragment unit observations tested eleven harmless names per implementation. Both guards accept ordinary names and reject several malformed/oversized names. PHP accepts `1org.example` and `0aa.example`; Rust's name expression rejects them. The current inspected Rust source retains that expression. This was not an HTTP or complete registration-validator test: PHP's original method checks a fixed synthetic extension payload, while Rust's original fragment checks names only. PHP 8.5.12/Rust 1.99.1 on one local macOS ARM64 host are not the qualified runtime/target matrix.

A uniform normative admission grammar was not established. The examined structural schema bounds name length; the prose requires preservation of accepted namespaced extensions. Intentional implementation-specific admission is a serious alternative to a product defect. The difference is retained for [the existing Protocol profile owner #55](https://github.com/RobLe3/IICP/issues/55), not silently fixed or treated as qualification invalidation.
