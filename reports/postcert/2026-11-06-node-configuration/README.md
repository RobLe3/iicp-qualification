# Node-configuration assertion scope

This informative source capsule maps nine existing Python, TypeScript and Rust case definitions to their exact public source assertions and 576 previously published coordinate references. It does not rerun them or change qualification credit.

The shared scenario labels do not imply identical inputs:

- Python and TypeScript check malformed named-node JSON and explicit absence of a saved node. Rust checks incomplete private-mode policy, including a positive completed-private-preset control, and CLI refusal before output is written.
- Python injects a destination write failure; TypeScript creates a directory collision; Rust makes an existing staged file read-only and checks its bytes remain unchanged. These are different failure fixtures, not interchangeable OS permission or ACL proofs.
- Source postconditions do not establish every actionable error path, successful private-file creation, owner-only storage guarantee or real Directory mode. No current product defect is inferred solely from these coverage limits.

Use [the machine-readable source map](source-map.json) for exact commits, source spans, postconditions, explicit limitations and existing coordinate links. Its references are public SDK/Protocol Git sources and the already published analysis-v2 derivative. Private root catalog prose, raw execution captures, host paths and private incident material are not included.

The original acceptance records remain authoritative. This is partial source interpretation, not complete catalog conformance, an executable frozen reference, a new runtime result, independent interoperability, a certificate, or release permission. Candidate, source and environment identities must still be resolved under the existing gates before any authorized reproduction.

The [versioned JSON Schema](source-map.schema.json) checks data shape. Source, coordinate and privacy validation plus independent review remain separate requirements.
